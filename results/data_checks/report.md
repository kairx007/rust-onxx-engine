## 2. Raw CSV structure

- Header fields 150 (first: `['', '0', '1', '2']`), 150 fields per row.
- Test rows 31,937; train rows 362,400 (training uses the first 200,000).
- Column 0 is a row index: True. Layout: raw col 0 = index; raw cols 1-40 = features; raw cols 145-149 = five label horizons (training uses 145).
- Label values (col 145): [1.0, 2.0, 3.0].

## 3. Normalization provenance

- Shipped `mu.npy`/`sigma.npy` vs stats of the first 50k training rows: max |Δμ| 8.8e-05, max |Δσ| 1.7e-05 → **they are the 50k-row smoke-run stats**.
- vs the first 200k rows that `train.py` trains on: max |Δμ| 0.557, max |Δσ| 0.617 (relative σ difference up to 118%). `train.py` never saves its stats, so every inference path (Python evaluate.py, C++, Rust) normalizes with statistics the models were not trained on.
- dataset.py stores sigma = std + 1e-8 and divides by it; Rust and C++ add 1e-8 again (negligible in float32).

## 4. Test arrays

- Processed test `.npz` = raw test normalized with the shipped stats: max diff 0.0e+00; labels = raw col 145 − 1: True.
- Phase 2 reconstructed CSV vs real raw: max feature error 7.1e-07, labels equal True → Phase 2 benchmark inputs are faithful.

## 5. Label semantics

- Raw col 146 example: label 1 → mid up 49% / down 15%; label 3 → up 17% / down 48%.
- label 1 is followed by rising mid-prices and label 3 by falling ones: 1=Up, 3=Down, so internal class 0=Up and 2=Down (the Rust Direction enum and the C++ printouts say 0=Down, 2=Up).

## 6. Window / label alignment

- Training: stride 1, label at row i+100 (tick after the window). C++ full_inference: stride 1, label at row i+100 (matches training).
- Rust engine before the fix: stride 100, label at row i+99 (last row of the window) — its label differed from the training-convention label for 28.2% of its 319 test windows.
- Rust engine now: stride configurable (default 1), label at row i+100 (matches training); on the full test CSV it evaluates the same 31,837 windows as C++ with identical correct counts (`results/phase2-cpp/rust_vs_cpp_eval/`).
